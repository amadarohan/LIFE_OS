# Life OS — Security

## 1. Threat model

Single user, single machine, local data. The realistic threats are:

| Threat | Mitigation |
|---|---|
| Another local process reading the DB or files | OS file permissions; DB uses Windows auth; secrets encrypted at rest |
| Accidental network exposure | Kestrel binds `localhost` only by default |
| Malicious file upload | Extension + content-type + size allowlist, stored under a fixed root, generated filenames |
| Path traversal via attachment/backup paths | All paths resolved through `SafePathResolver`, which rejects rooted paths and `..` segments and asserts the result stays under the configured root |
| Prompt injection from notes/journal | User content wrapped as data; `PromptInjectionGuard`; tools are typed and validated |
| Secret leakage in logs | Serilog destructuring excludes `ApiKey`, `Password`, `Token`; `AppSetting.IsSensitive` values are never logged |
| Secret leakage in source control | `appsettings.Local.json` and `secrets/` are git-ignored; keys come from user secrets or the encrypted settings store |
| Destructive operation by mistake | Restore/delete require typed confirmation; backups validated before restore |
| CSRF on Blazor forms | `UseAntiforgery()` + Blazor's built-in antiforgery on form posts |
| Information disclosure | Production error page shows a correlation id only, never a stack trace |

## 2. Network

- `applicationUrl` defaults to `https://localhost:7xxx;http://localhost:5xxx`.
- `Network:AllowLanAccess` (default `false`) is the only way to bind `0.0.0.0`, and the UI warns
  that the app has no authentication.
- No outbound calls except to the AI provider endpoints the user configures.

## 3. Secrets

- AI API keys are stored in `AppSettings` with `IsSensitive = true`, encrypted by
  `DpapiSecretProtector` (Windows DPAPI, current user scope). On non-Windows the app falls back
  to a key file under `Storage:SecretsRoot` with a startup warning.
- Keys are never returned to the browser in plaintext; the settings UI shows `••••••••` and a
  "replace" action.
- Keys are never written to `AuditLog`, `AIExecutionLog`, or Serilog output.
- `appsettings.json` contains placeholders only.

## 4. Input validation

- Every Application command has a FluentValidation validator.
- Blazor forms use `EditForm` + `DataAnnotationsValidator` for immediate feedback, and the
  Application validator is authoritative.
- AI tool inputs are validated independently of the model's claims.
- Imported JSON is schema-checked and size-limited before deserialization.

## 5. File handling

- Uploads: max 25 MB, allowlist of extensions, content-type cross-check, SHA-256 checksum,
  stored as `{yyyy}/{MM}/{guid}{ext}` under `Storage:AttachmentsRoot`.
- Downloads: served through a controller that resolves the stored relative path safely and
  sets `Content-Disposition: attachment`.
- Backups: written under `Storage:BackupsRoot`, filename generated by the app, never user-supplied.

## 6. Data protection

- Financial and journal data are marked `Sensitive` in the AI context engine.
- Cloud AI providers are blocked for sensitive payloads unless
  `AI:AllowSensitiveDataToCloud = true` **and** the user has confirmed in Settings.
- Export excludes secrets by default (`IncludeSecrets = false`).

## 7. Logging

- Serilog writes to console + rolling file under `Storage:LogsRoot`.
- Request logging excludes query strings on finance routes.
- Exceptions are logged with full detail server-side; the UI receives a correlation id.

## 8. Backup and restore

- Backup produces a `.zip` containing a `BACKUP_MANIFEST.json` (schema version, app version,
  created-at, table row counts, checksums) plus the data export and attachments.
- Restore validates the manifest, checks schema compatibility, shows a diff summary of what
  will be replaced, and requires the user to type `RESTORE` to proceed.
- A pre-restore safety backup is created automatically.
- Restore runs inside a transaction where possible; attachments are swapped after the DB commit
  with a rollback copy retained.

## 9. What is explicitly out of scope

No authentication, no multi-user authorization, no TLS certificate management, no bank
integration, no cloud sync. If the app is ever exposed beyond localhost, authentication must be
added first — this is documented in `LOCAL_SETUP.md`.
